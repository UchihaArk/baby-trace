# 睡眠手动记录 + 辅食功能 实施方案

## 核心设计

**睡眠改造**：复用现有 `startTime`/`endTime` 机制。手动输入小时数 → `endTime = startTime + 小时 × 3600`，`amount = null`。现有所有统计/展示代码（stats.ts 的 `endTime - startTime` 聚合、timeline 区间显示、describeLog 时长）**零改动**即正确工作。

**辅食新增**：新增 `food` 活动类型。名称存 `details = { name: string }`（与 feed/diaper 等结构一致）。5 个分类作 Chip 快捷填充名称框，可自由编辑，最终只存一个 `name`。

export const activityTypes = ["feed", "diaper", "sleep", "pump", "bath", "haircut", "nail", "food"] as const;

### 2. `server/inputs.ts`
- 第 3 行 `activityTypeSchema` 的 enum 追加 `"food"`
- 新增辅食详情 schema 并加入 union（约第 30 行）：
```ts
/** 辅食详情：食物名称（分类快捷填充或自定义） */
export const foodDetailsSchema = z.object({
  name: z.string().trim().min(1).max(40),
});
export type FoodDetails = z.infer<typeof foodDetailsSchema>;
```
- `detailsSchema` union 追加 `foodDetailsSchema`；`LogDetails` 类型追加 `FoodDetails`

### 3. 生成数据库迁移
运行 `npx drizzle-kit generate`。SQLite 的 text enum 无 CHECK 约束，预计无 SQL 变更（仅 meta snapshot 更新）。若 drizzle 报"No schema changes"则跳过。

> 后端 `logs.ts` 的 POST/PATCH 已是通用逻辑，天然支持 food；`stats.ts` 的 if-else 不匹配 food 分支即忽略，安全；`sleep.ts` toggle 端点保留不动。

## 三、前端 — 新建两个 Drawer

### 6. `components/log-entry/sleep-drawer.tsx`（新建）
模仿 `care-drawer.tsx`（最简抽屉），核心字段：
- **时长**：大数字 + "小时"，`[-]`/`[+]` 步进 0.5，默认 2，范围 0.5–12
- **快捷预设**：`[1] [1.5] [2] [2.5] [3]`（Chip）
- **时间**：`datetime-local`，默认当前时刻（支持补记）
- **备注**：可选 Input
- 提交：`endTime = localInputToSec(at) + Math.round(hours * 3600)`，复用 `createLog`/`updateLog`
- 编辑回填：从 `(endTime - startTime) / 3600` 反推小时数
- 主题色 indigo（沿用睡眠配色）

### 7. `components/log-entry/food-drawer.tsx`（新建）
模仿 `care-drawer.tsx`，核心字段：
- **分类 Chip**（5 个，点击将短名填入名称框）：
  - 🌾 谷物主食 / 🥣 冲调辅食 / 🥫 果蔬肉泥 / 🍪 辅食零食 / 🫗 调味与油
- **名称**：Input，必填（点分类自动填，可改具体食物如"米粉"）
- **时间**：`datetime-local`，默认当前
- **备注**：可选 Input
- 提交：`details = { name }`，复用 `createLog`/`updateLog`
- 主题色 orange
